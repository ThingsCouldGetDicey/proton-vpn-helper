# Browser routing verification

This project deals with browser proxy settings, so a successful build and a saved country preference are **not** sufficient evidence that routing works.

## What we have tested

The isolated Chromium test `tests/pac_transport_integration.py` starts three temporary HTTPS proxy listeners on the same computer. It loads the actual built extension, installs a PAC configuration generated by the project's routing code, and makes synthetic browser requests.

| Test request | Observed destination |
| --- | --- |
| `first.example.com` assigned `CH` | Local HTTPS proxy A |
| `second.example.com` assigned `NL` | Local HTTPS proxy B |
| `unassigned.example.com` | Local default HTTPS proxy |
| `blocked.example.com` with no eligible exit | No fallback to any other test proxy |

The test asserts that the three normal requests reach the correct listener and don't appear at the wrong one. It also checks that the helper controls Chromium's proxy settings. It generates its own short-lived test certificate and private key under a temporary folder and removes them afterwards.

Run:

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run build
python3 tests/pac_transport_integration.py
```

Requires Chromium, matching ChromeDriver, Python requests and OpenSSL. It does not need Proton credentials or an external network connection.

The separate `tests/browser_integration.py` checks the real options interface, saved policy, Remove action, explicit disconnected status and optional local native messaging.

## What that does **not** establish

The synthetic endpoints are **not Proton VPN servers**. The country labels are test data, not observed geographic locations. We still need a separate human-authorised Proton sign-in and live tests showing that:

- A named website exits via the requested country while an unassigned site uses the normal country.
- Proton's server/proxy authentication accepts simultaneous endpoints.
- DNS, WebRTC, redirects and third-party/CDN requests don't create unintended bypasses.
- Proxy conflicts, connection loss and unsupported country requests fail safely.
- User-selected split-tunnelling Include/Exclude rules retain their intended precedence.

Do not use the experimental profile for sensitive browsing or submit the extension to a marketplace until these checks are recorded with real evidence. The project tracks release blockers in [the marketplace checklist](STORE_READINESS.md).

## Toolbar and split-tunnel interaction tests

Run `python3 tests/toolbar_integration.py`. Isolated Chromium verifies the toolbar action and keyboard shortcut are registered, a saved two-letter country rule produces a neutral tab badge, that disconnected VPN status remains visible, exact Exclude and Include-only rules can be updated on explicit user click, broad parent exclusions are never silently removed, and the original Proton controls remain accessible. No live Proton account session is used.
